# Document Processing Microservice (beta)

## Описание

Демосервис для автоматизированной обработки документов: выравнивает страницы, распознаёт текст и извлекает банковские реквизиты. Работает через веб-интерфейс Streamlit.
Для развертывания необходим подготовленный и запущенный Docker Desktop.

## Функции

- **Выравнивание:** поворот кратно 90° через Tesseract OSD и точная корректировка наклона по линиям.
- **Распознавание текста (OCR):** Используется open source OCR движок - Tesseract (rus), перед распознаванием стираются линии таблиц.
- **Парсинг реквизитов:** Производится через регулярные выражения (regex): ИНН (10/12 цифр), КПП (9), БИК (9), расчётный и корреспондентский счета (20). Учитываются варианты подписей (`р/с`, `р/сч`, `Расчётный счёт`, `к/с`, `Корр. счёт`, `ИНН/КПП 7707083893/773601001`, `Сч. №`), счета, напечатанные группами цифр, и латинские буквы-двойники после OCR.
- **Проверка:** контрольные цифры ИНН и ключ счёта по БИК (алгоритм ЦБ РФ); не прошедшие проверку значения попадают в `warnings` страницы.
- **Многостраничные документы и пакеты файлов:** каждая страница PDF распознаётся отдельно, несколько загруженных файлов обрабатываются последовательно друг за другом.

## Запуск

```bash
docker compose up --build
```

Вэбинтерфейс: http://localhost:8501. Логи этапов обработки можно посмотреть в контейнере: `docker compose logs -f app`.
Часовой пояс для поля `processed_at` задаётся переменной `TZ` в `docker-compose.yml`.

## Использование

1. Загрузить один или несколько файлов PDF, JPG или PNG.
2. При необходимости отметить «Вернуть распознанный текст».
3. Нажать «Отправить на распознавание». Файлы обрабатываются по очереди, статусбар показывает текущий файл, страницу и этап.
4. Результат по каждому файлу показывается в формате JSON, его можно скачать в TXT. Для нескольких файлов есть кнопка «Скачать все результаты в TXT» (массив JSON).

Пример результата для одного файла:

```json
{
  "document_name": "invoice.pdf",
  "processed_at": "2026-10-28 18:42",
  "code": 0,
  "message": "Обработано успешно",
  "requisites": {
    "inn": ["7707083893", "1234567890"],
    "kpp": ["773601001"],
    "bik": ["044525225"],
    "settlement_account": ["40702810603800001234"],
    "correspondent_account": ["30101810400000000225"]
  },
  "pages": [
    {
      "page": 1,
      "code": 0,
      "message": "Обработано успешно",
      "requisites": {
        "inn": ["7707083893", "1234567890"],
        "kpp": ["773601001"],
        "bik": ["044525225"],
        "settlement_account": ["40702810603800001234"],
        "correspondent_account": ["30101810400000000225"]
      },
      "warnings": [
        {"code": 301, "message": "Реквизит не прошёл проверку контрольной суммы", "field": "inn", "value": "1234567890"}
      ],
      "text": "..."
    },
    {
      "page": 2,
      "code": 203,
      "message": "На странице не найден текст",
      "requisites": {"inn": [], "kpp": [], "bik": [], "settlement_account": [], "correspondent_account": []},
      "warnings": [],
      "text": ""
    }
  ]
}
```

`requisites` верхнего уровня — сводка уникальных значений со всех страниц, `pages` — результат распознавания каждой страницы. Поле `text` у страниц возвращается только при включённом флаге.

## Коды ошибок

| Код | Описание | Поведение |
|-----|----------|-----------|
| 0   | Обработано успешно | код документа или страницы |
| 101 | Неподдерживаемый формат файла | обработка файла прерывается, следующие файлы обрабатываются |
| 102 | Файл пустой | обработка файла прерывается |
| 103 | Файл повреждён или не может быть открыт | обработка файла прерывается |
| 104 | PDF защищён паролем | обработка файла прерывается |
| 201 | Не удалось преобразовать страницу в изображение | код страницы, остальные страницы обрабатываются |
| 202 | Ошибка распознавания текста (OCR) | код страницы (+ поле `error`), остальные страницы обрабатываются |
| 203 | На странице не найден текст | код страницы, остальные страницы обрабатываются |
| 301 | Реквизит не прошёл проверку контрольной суммы | в `warnings` страницы с полями `field` и `value` |
| 302 | Реквизиты не найдены | код страницы или всего документа |
| 303 | Текст не распознан ни на одной странице | код документа |
| 500 | Внутренняя ошибка сервиса | код документа, подробности в логах |

## Ограничения

- Отсутствует логика параллельной обработки,
- Выбрана самая легкое OCR решение без предобработки входного изображения,
- Отсутствует определение типа документа и нет логики получения других типов информации (требует либо конретной донастройки в коде или подключение LLM),
- Отсутствует логика очередей и нет логики во вне программы (все локально)

## Что нужно реализовать для деплоя

- очереди (RabbitMQ/Kafka),
- multiprocessing,
- более точную модель OCR (возможно с интеграцией в gpu),
- Для "умного" парсинга текста без привязки к коду необходима интеграция с LLM, реализация эмбендингов, сторонние модели для сигментации отдельных объектов,
- Предобработка изображения/документа методами компьютерного зрения,
- Полноценный пайплайн для отслеживания изменений с автоматизацией CI/CD
